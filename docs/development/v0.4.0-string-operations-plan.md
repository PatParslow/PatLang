# Patlang v0.4.0: String Operations - Implementation Plan

## Overview

**Version**: v0.4.0  
**Focus**: String Operations  
**Strategic Priority**: Critical Blocker #2 for Self-Hosting  
**Timeline**: 3 weeks  
**Dependencies**: v0.3.0 Control Flow Structures (COMPLETE)  

## Strategic Context

String operations are identified as **Critical Blocker #2** in the self-hosting gap analysis. Without string handling capabilities, we cannot implement:
- Source code parsing and manipulation
- Token stream processing with string literals
- Error message generation and formatting
- File path handling and name processing
- Function name resolution and parameter handling

This makes v0.4.0 essential for building the foundation needed for functions and ultimately self-hosting capability.

#### 2.3 String Processing Logic
```ruby
def tokenize_string
  start_pos = @position
  @position += 1  # Skip opening quote
  value = ""
  
  while @position < @input.length && @input[@position] != '"'
    if @input[@position] == '\\'
      # Handle escape sequences
      @position += 1
      if @position < @input.length
        case @input[@position]
        when 'n'
          value += "\n"
        when 't'
          value += "\t"
        when 'r'
          value += "\r"
        when '\\'
          value += "\\"
        when '"'
          value += '"'
        else
          value += @input[@position]
        end
      end
    elsif @input[@position] == '#' && @position + 1 < @input.length && @input[@position + 1] == '{'
      # Handle string interpolation start
      return create_interpolated_string_tokens(value, start_pos)
    else
      value += @input[@position]
    end
    @position += 1
  end
  
  if @position >= @input.length
    raise LexerError, "Unterminated string literal"
  end
  
  @position += 1  # Skip closing quote
  Token.new(:STRING, value, start_pos)
end
```

#### 3.1 Grammar Rules
Extend [`patlang-core/parser/parser.rb`](patlang-core/parser/parser.rb:1) with new productions:

```
method_call → index_access (DOT IDENTIFIER (LPAREN argument_list? RPAREN)?)*
index_access → primary (LBRACKET expression RBRACKET)*
primary → STRING | STRING_INTERPOLATION | NUMBER | BOOLEAN | IDENTIFIER | LPAREN expression RPAREN

string_interpolation → interpolated_parts
interpolated_parts → STRING_PART (INTERPOLATION_START expression INTERPOLATION_END STRING_PART)*
```

### Phase 4: Evaluator Logic (Week 2-3)

#### 4.1 String Evaluation
Extend [`patlang-core/evaluator/evaluator.rb`](patlang-core/evaluator/evaluator.rb:9) with new `visit_*` methods:

```ruby
def visit_string_node(node)
  node.value
end

def visit_string_concatenation_node(node)
  left_value = evaluate(node.left)
  right_value = evaluate(node.right)
  
  # Convert both operands to strings
  left_str = convert_to_string(left_value)
  right_str = convert_to_string(right_value)
  
  left_str + right_str
end

def visit_method_call_node(node)
  object_value = evaluate(node.object)
  method_name = node.method_name
  
  # Handle built-in string methods
  if object_value.is_a?(String)
    case method_name
    when "length"
      object_value.length
    when "uppercase"
      object_value.upcase
    when "lowercase"
      object_value.downcase
    when "trim"
      object_value.strip
    when "substring"
      start_pos = evaluate(node.arguments[0])
      end_pos = evaluate(node.arguments[1]) if node.arguments[1]
      if end_pos
        object_value[start_pos...end_pos]
      else
        object_value[start_pos..-1]
      end
    else
      raise "Unknown string method: #{method_name}"
    end
  else
    raise "Method calls not supported for #{object_value.class}"
  end
end

def visit_index_access_node(node)
  object_value = evaluate(node.object)
  index_value = evaluate(node.index)
  
  if object_value.is_a?(String)
    if index_value.is_a?(Integer)
      # Handle negative indexing
      actual_index = index_value < 0 ? object_value.length + index_value : index_value
      
      if actual_index >= 0 && actual_index < object_value.length
        object_value[actual_index]
      else
        raise "String index out of bounds: #{index_value}"
      end
    else
      raise "String index must be an integer"
    end
  else
    raise "Index access not supported for #{object_value.class}"
  end
end

def visit_string_interpolation_node(node)
  result = ""
  
  node.parts.each do |part|
    if part.is_a?(StringNode)
      result += part.value
    else
      # Evaluate expression and convert to string
      value = evaluate(part)
      result += convert_to_string(value)
    end
  end
  
  result
end

private

def convert_to_string(value)
  case value
  when String
    value
  when Numeric
    value.to_s
  when TrueClass, FalseClass
    value.to_s
  when NilClass
    ""
  else
    value.to_s
  end
end
```

#### 4.2 String Comparison Support
Extend comparison operations to handle strings:

```ruby
def visit_comparison_node(node)
  left_value = evaluate(node.left)
  right_value = evaluate(node.right)
  
  # Handle string comparisons
  if left_value.is_a?(String) || right_value.is_a?(String)
    left_str = convert_to_string(left_value)
    right_str = convert_to_string(right_value)
    
    case node.operator
    when '=='
      left_str == right_str
    when '!='
      left_str != right_str
    when '<'
      left_str < right_str
    when '>'
      left_str > right_str
    when '<='
      left_str <= right_str
    when '>='
      left_str >= right_str
    else
      raise "Unknown comparison operator: #{node.operator}"
    end
  else
    # Existing numeric comparison logic
    case node.operator
    when '=='
      left_value == right_value
    when '!='
      left_value != right_value
    when '<'
      left_value < right_value
    when '>'
      left_value > right_value
    when '<='
      left_value <= right_value
    when '>='
      left_value >= right_value
    else
      raise "Unknown comparison operator: #{node.operator}"
    end
  end
end
```

## Architecture Decisions

### String Representation
- **Decision**: Use Ruby native strings for internal representation
- **Rationale**: Leverages Ruby's robust string handling and Unicode support
- **Impact**: Simplified implementation, excellent performance

### Method Call Syntax
- **Decision**: Use dot notation (`string.method()`) for string methods
- **Rationale**: Familiar syntax from many programming languages
- **Impact**: Foundation for future object-oriented features

### String Interpolation
- **Decision**: Use `#{expression}` syntax for interpolation
- **Rationale**: Ruby-like syntax, clear expression boundaries
- **Impact**: Requires careful lexer/parser coordination

### Index Access
- **Decision**: Use bracket notation (`string[index]`) for character access
- **Rationale**: Consistent with array-like access patterns
- **Impact**: Foundation for future array implementation

## Risk Assessment

### High Risk Areas
1. **Lexer Complexity**: String parsing with escape sequences and interpolation
2. **Grammar Complexity**: Method calls and indexing add parsing complexity
3. **Performance**: String operations could impact evaluator performance
4. **Memory Usage**: String concatenation and manipulation memory patterns

### Mitigation Strategies
1. **Incremental Testing**: Test each string component thoroughly
2. **Clear Error Messages**: Invest in high-quality string error reporting
3. **Performance Monitoring**: Benchmark string operations early
4. **Memory Management**: Monitor string creation and garbage collection
